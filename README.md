# 播浪

中文名：**播浪** · 前缀 `livewave` · 端口 **6400 / 11400**

## 骨架

**互动事件入流 → 事件时间水位线推进 → 热度窗关闭发射 → 迟到修正/撤回 → 窗输出与撤回互证**

皮：直播间点赞/送礼互动。去皮是事件时间窗计算 + 允许迟到与撤回，不是直播运营后台 CRUD，不是点击会话空闲切开。

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6400
# 入流 → 灌「准时热度样例」→ 水位线/热度窗 → 再灌「迟到修正样例」看撤回
# → 再灌「迟到修正重放样例」原包重放：合计不变、撤回不增、幂等命中+1 → 贯验
# → 「先撤回证明核证」看证明号四方对账
```

## 先撤回证明（已实现 · 乙：证明号换审计行）

同一迟到事件第二次走进修正入口时，接口仍回「已处理」，由先撤回证明号兜底。全局只贯彻一种架构，本库选 **乙**：

- **首撤同票落证明**：首次迟到修正成功，在同一个 `BEGIN IMMEDIATE` 写事务内落 `先撤回证明`（事件编号、窗键、首撤哈希、证明号）。证明号由 `(窗键, 事件编号, 首撤哈希)` 派生、全局唯一、可按撤回簿重算。落证明失败整票回滚——**禁止命中成功而证明空**。
- **二次入口按证明号消化**：重放票在修正点见证明号，只落一条唯一键含证明号的命中审计行（`撤回幂等审计.证明号`，命中次数+1）——**禁止持证明号仍把累计再加一遍**、**禁止第二笔业务撤回行**；无证明号不得只靠窗键去重蒙混（有撤回无证明即判分叉，整票回滚）。
- **提交前互证**：每批装载提交前核对撤回簿 ↔ 先撤回证明一一对应——**禁止证明号与撤回簿行数分叉还提交**；窗互证（贯验）另把守缺证明/孤证明/双证明/哈希不符/审计证明号不符。
- **旧库自愈**：启动迁移给 `撤回幂等审计` 加证明号列、按撤回簿回填证明与审计证明号，最后才建唯一索引（`先撤回证明_锚点`、`先撤回证明_证明号`、`撤回幂等审计_证明号`）。
- **核证只读接口**：`GET /api/核证/先撤回证明?事件编号=`（可空，空则核证全表最近 50 条）→ 证明行 enriched（撤回行数、幂等命中、哈希核证、窗合计）、valid、问题；并反抓「撤回簿有行而证明缺失」的半截。纯读，无副作用。
- 取舍甲（证明号短路：见证明号整票短路、不写事件行也不强制审计）未采用，分叉留档于 `backend/app/modules/先撤回证明/__init__.py` 模块文档。

## 撤回幂等（已实现 · 口径B：窗键+事件编号撤回幂等锚点）

同一事件编号对同一热度窗的迟到修正必须幂等，全局只贯彻一种架构，本库选 **口径B**：

- **锚点**：撤回单部分唯一键 `(窗键, 事件编号)`（仅约束「迟到修正」），另有 `撤回幂等审计` 表记首次/末次/命中次数。
- **重放口径**：重放票不在入流门整票跳过——水位推进、关窗扫描照常参与；到已关闭窗修正点时，锚点已存在则只累加命中审计，**窗合计不二次累加、撤回单不增行**。互动事件主键仍是物理行守卫（同事件编号至多一行）。
- **失败闭**：每批装载在单个 `BEGIN IMMEDIATE` 写事务内（WAL + busy_timeout），锚点 INSERT 成功才允许加合计/写撤回；任何唯一约束撞车整批回滚，杜绝「合计双加、撤回一行」或「撤回两行、合计一次」的半截分叉。
- **旧库自愈**：启动迁移先清重复撤回、按事件表重算窗合计、回填审计，最后才建唯一索引。
- **只读接口**：`GET /api/撤回幂等?事件编号=&窗键=`（窗键可空，按事件时反推）→ 是否二次、幂等命中、合计、撤回行数、事件行数、valid、锚点口径。
- 口径A（事件编号全局整票跳过）与口径B 的正确性分叉留档于 `backend/app/services/撤回幂等.py` 模块文档；两口径行数值结论相同（事件行/撤回行恒 1、合计不双加），差别在命中点与保证机制。

## 主链对象

| 对象 | 作用 |
| --- | --- |
| 互动事件 | 带事件时/处理时的点赞送礼 |
| 水位线 | 每房事件时水位 + 允许迟到秒 |
| 热度窗 | 翻滚窗；开启累计，关闭发射 |
| 撤回单 | 已关闭窗被允许迟到事件修正 |
| 旁路匣 | 超允许迟到 |
| 窗贯验 | 窗合计 ↔ 事件合计 ↔ 末次撤回 |
